# Subscription Integration Blueprint & Architecture

This document provides the blueprint and step-by-step layout for integrating a central admin subscription control system into the **Passport Photo Generator** React + Electron desktop application, matching the architecture utilized in the pathology lab software (`offline_lab_1` and `admin_dashboard_lab`).

---

## 1. Core Architecture Overview

The system consists of two primary components communicating secure payloads:
1. **Desktop Client (Passport Photo Generator)**: A fully offline-capable React + Electron desktop app that reads local system specifications (Machine GUID), validates license keys offline via symmetric key decryption, and checks in with the server periodically when online.
2. **Subscription Admin Portal (Dashboard)**: A Next.js web application connected to Supabase (or fallback file database) where administrators can register licenses, pause/stop subscription statuses, track expiration dates, and generate cryptographically signed keys.

```
+------------------------------------+
|     Admin Dashboard Web App       |
|  - Register Customers/Machine ID   |
|  - Set Status (Active/Paused/Stop)  |
|  - Endpoint: /api/license/status   |
+-----------------+------------------+
                  |
         (Internet/Online HTTP GET)
                  |
                  v
+------------------------------------+
|  Photo Generator (Desktop Client)  |
|  - React Frontend (Lock Screen)    |
|  - Preload IPC Bridge              |
|  - Electron Main Process (Registry)|
+------------------------------------+
```

## 2. Cryptographic Security (AES-256-CBC)

License keys are generated by encrypting a payload containing the unique **Machine ID** and the **Expiration Date** separated by a pipe character (`|`):

`Payload = MachineId | ExpirationDate`

### Key Generation Steps
1. **Secret Salt Key**: A shared salt (e.g., `process.env.LICENSE_SECRET_SALT`) is hashed using **SHA-256** to derive a 32-byte key.
2. **IV (Initialization Vector)**: A cryptographically secure random 16-byte IV is generated for each key to prevent replay attacks.
3. **AES-256-CBC Encryption**: The payload is encrypted with the key and IV.
4. **License Key Output**: The IV (32 hex characters) is prepended to the ciphertext, resulting in a single unified uppercase hex string.
5. **Decryption & Validation**: The client splits the first 32 characters as the IV, decrypts the remainder, matches the Machine ID, and checks the date.

## 3. Implementation Steps for Passport Photo Generator

To integrate this licensing logic, we need to make the following changes:

### Step 1: Preload Configuration (`electron/preload.js`)
Expose the Electron API methods so the Next.js React frontend can trigger license checks:
```javascript
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('electronAPI', {
  platform: process.platform,
  licenseCheck: () => ipcRenderer.invoke('license-check'),
  licenseActivate: (key) => ipcRenderer.invoke('license-activate', key),
  licenseRequestTrial: () => ipcRenderer.invoke('license-request-trial'),
});
```

### Step 2: Electron Main Process (`electron/main.js`)
Integrate local key verification, trial locks, and Registry reading:
1. **Get Machine ID**: Fetch the unique hardware UUID (`MachineGuid`) via Windows Registry.
2. **validateLicenseKey()**: Cryptographically verify the license format, hardware ID, and expiry date.
3. **IPC Handlers**:
   - `license-check`: Returns validity and expiration from local store (e.g. SQLite database or config file).
   - `license-activate`: Saves verified license key.
   - `license-request-trial`: Generates a local 7-day trial key and creates a persistent `trial.json` in the user's local app directory to block duplicate trial requests.

### Step 3: Local Settings Storage
Add a helper to read/write settings or update local database:
- Read local JSON file `settings.json` in Electron's `userData` folder to persist the license key:
```javascript
// Example in main.js
const fs = require('fs');
const settingsPath = path.join(app.getPath('userData'), 'settings.json');
```

### Step 4: React License Provider Context (`components/LicenseProvider.tsx`)
Create a provider that wraps the app and acts as the gatekeeper:
1. **Online Verification Proxy**: If online, call the server `/api/license/remote-check?machineId=...` (timeout after 2.5 seconds to preserve offline performance).
   - If response status is `PAUSED` or `STOPPED`, lock the application dashboard immediately.
   - If status is `ACTIVE` and key changed, write the new key locally (auto-renew).
   - If status is `DELETED`, wipe the local key and lock the screen.
2. **Offline Fallback**: If offline, validate the locally saved key using `electronAPI.licenseCheck()`.
3. **Activation UI Screen**: If no valid license exists, block routing and render a dark activation lock screen showing:
   - Unique Machine ID (with a copy button).
   - Text area to paste license key.
   - Activation buttons.
   - "Start 7-Day Free Trial" button.

### Step 5: Application Wrapper (`app/layout.tsx`)
Wrap Next.js `{children}` with `<LicenseProvider>`:
```typescript
import { LicenseProvider } from "@/components/LicenseProvider";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <LicenseProvider>{children}</LicenseProvider>
      </body>
    </html>
  );
}
```

## 4. Adapting the Admin Dashboard Website

To build the companion dashboard web portal:
1. **Clone the Admin Dashboard project**: Copy `admin_dashboard_lab` into a new folder `admin_dashboard_photo`.
2. **Rename branding & title components**:
   - Change references from "Pathology LIS" / "JharLab" to "Passport Photo Generator Admin Console".
3. **Database Configuration**:
   - Set up a Supabase table `customers` with fields:
     - `id` (UUID)
     - `created_at` (timestamp)
     - `business_name` (replaces `lab_name`)
     - `owner_name` (text)
     - `phone` (text)
     - `machine_id` (text, indexed)
     - `expiry_date` (timestamp)
     - `license_key` (text)
     - `status` (text: `'ACTIVE'` | `'PAUSED'` | `'STOPPED'`)
4. **Subscription Period Actions**:
   - Provide subscription plans (e.g. 1 Month, 6 Months, 1 Year) which compute the respective `expiry_date and generate the AES hex string.
